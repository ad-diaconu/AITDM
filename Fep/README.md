# Running the WISDM federated experiments on fep (Slurm)

fep (`fep.grid.pub.ro`) is the university cluster and the place where our experiments run.
You log in to a shared **login node** and ask **Slurm** to run the work on a compute node, as *jobs*.
This folder holds the fep setup and the job scripts; it is adapted from the course tutorial
([AITDM_FLOWER_PROJECT_TUTORIAL/Fep](https://github.com/Chiru-CatalinMihail/AITDM_FLOWER_PROJECT_TUTORIAL/tree/main/Fep)).

## Quick start (new clone)

```bash
ssh <your.username>@fep.grid.pub.ro
git clone https://github.com/ad-diaconu/AITDM.git ~/AITDM_Project/AITDM
cd ~/AITDM_Project/AITDM
bash Fep/setup_fep.sh                     # once: .venv + data/ -> ~/AITDM_Project/data
bash Fep/submit.sh smoke_test             # a few minutes; the log must end with SMOKE TEST PASSED

bash Fep/submit.sh reproduce data         # WISDM archive -> windows -> all partitions (CPU job)
bash Fep/submit.sh centralised_array      # Stage 1 baseline: 2 models x 5 folds x 3 seeds (GPU)
bash Fep/submit.sh --array=0-8%2 fl_array experiments/runs/fl_primary.txt   # FL matrix (GPU)
squeue --me                               # what is running / waiting
```

## Moving an existing fep clone to this layout (do this BEFORE `git pull`)

`data/` is no longer tracked by git (it is regenerated by `data_splitting/`). Pulling the commit
that stops tracking it **deletes the tracked files of `data/` from your clone**. Move it out first:

```bash
cd ~/AITDM_Project/AITDM                          # your existing clone
mkdir -p ~/AITDM_Project/data
cp -a data/. ~/AITDM_Project/data/ && rm -rf data # windows.npz, partitions/, raw/ are now safe
git pull                                          # (or git switch <branch>)
bash Fep/setup_fep.sh --container                 # links data/ back; keeps using the container + venv
                                                  # of the existing results (or no option: a new .venv)
```

The trained models (`outputs/**/*.pt`) were never tracked, so `git pull` leaves them alone.
`experiments/summarize_fl.py` needs the centralised `model.pt` files, so keep them.

## Where everything is

```text
~/AITDM_Project/
├── AITDM/                      <- the clone (code; .venv if you use one); can be re-cloned
│   ├── data    -> ~/AITDM_Project/data      (link created by setup_fep.sh; git-ignored)
│   ├── logs    -> ~/AITDM_Project/logs      (SuperLink / SuperNode logs of deployment jobs)
│   ├── outputs/                             <- results: results.json, summaries, reports ARE committed,
│   │                                           model weights (*.pt) are not
│   └── Fep/
│       ├── setup_fep.sh        <- the one-time setup
│       ├── submit.sh           <- bash Fep/submit.sh [sbatch options] JOB [arguments]
│       ├── my_partitions.sh    <- which partitions (queues) your account may use
│       └── jobs/               <- one .sbatch file per job (table below)
├── data/                       <- raw/wisdm/, wisdm/windows.npz, partitions/wisdm/<split>_K<K>/fold<f>/
├── slurm/aitdm-<job>-<jobid>.out  <- the log of every job (aitdm-<job>-<jobid>_<task>.out for arrays)
└── WISDM_at_latest.tar.gz      <- the raw archive
```

| Job | Runs | Default resources |
|---|---|---|
| `smoke_test` | `tests/smoke_test.sh`: the whole pipeline on synthetic data | haswell, 4 CPUs, 30 min |
| `reproduce` | `experiments/reproduce.sh [data\|central\|fl\|summary]` (sequential) | haswell, 16 CPUs, 12 h |
| `centralised_array` | `experiments/centralised.py`, task = (model, fold) | dgxa100, 1 GPU, 30 min, array 0-9%2 |
| `fl_array` | `experiments/run_seeds.py`, task = one line of a run list in `experiments/runs/` | dgxa100, 1 GPU, 4 h |
| `simulation` | `scripts/run_simulation.sh`: one `flwr run` on one fold (ad-hoc runs) | haswell, 8 CPUs, 2 h |
| `deployment` | SuperLink + one SuperNode per client, connected by IP address | haswell, 6 tasks x 2 CPUs, 1 h |
| `command` | any command (`split_data.py`, `summarize_fl.py`, explainability, ...) | haswell, 4 CPUs, 1 h |
